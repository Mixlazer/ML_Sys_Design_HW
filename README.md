# ML_Sys_Design_HW

Проектный репозиторий курса по дизайну ML-систем.
Работы ведутся в ветках `hw_n` и попадают в `main` через pull request.

## Smart LLM Router

Интеллектуальная маршрутизация между языковыми моделями с учётом сложности
запроса, предметной области и языка. Цель — снизить стоимость обработки запросов,
сохранив качество ответов и приемлемую задержку.

### Задача

Использование одной дорогой LLM для всех запросов может создавать лишние затраты,
а выбор дешёвой модели — ухудшать ответы на сложные вопросы.
Маршрутизатор должен выбирать подходящую модель для каждого запроса:

1. Определить язык, домен и признаки сложности запроса.
2. Оценить качество доступных LLM по результатам бенчмарков.
3. Учесть ограничения по стоимости и времени ответа.
4. Вызвать выбранную LLM и вернуть ответ с метаданными выбора.

Планируется сравнение с фиксированной моделью, самой дешёвой допустимой LLM
и выбором по таблице бенчмарков. Основные метрики — качество ответов,
средняя стоимость запроса и задержки p50/p95.

## Разработка

Требуются Python 3.11+, Git и интернет для установки инструментов.
Зависимости для разработки указаны в `pyproject.toml`, в extra `dev`.

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -X utf8 -m pre_commit install
.\.venv\Scripts\python.exe -m pre_commit run --all-files
```

Режим UTF-8 при установке хука нужен для корректной обработки путей с кириллицей.

### Linux / macOS

```shell
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/python -m pre_commit install
.venv/bin/python -m pre_commit run --all-files
```

Ruff используется как линтер и форматер. Хуки дополнительно проверяют YAML/TOML,
пробелы, окончания файлов, конфликты слияния, приватные ключи и размер файлов.
Для ручной проверки Python-кода запустите `python -m ruff check .`
и `python -m ruff format --check .` интерпретатором из `.venv`.
Хуки устанавливаются в каждой локальной копии репозитория; если они исправили
файлы, изменения нужно проверить и повторно добавить через `git add`.
