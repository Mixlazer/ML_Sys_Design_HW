# ML_Sys_Design_HW

Проектный репозиторий курса по дизайну ML-систем.
Работы ведутся в ветках `hw_n` и попадают в `main` через pull request.

## Smart LLM Router

Интеллектуальная маршрутизация между языковыми моделями с учётом сложности
запроса, предметной области и языка. Цель — снизить стоимость обработки запросов,
сохранив качество ответов и приемлемую задержку.
Поддерживаются готовые модели у локальных и облачных провайдеров.
Автоподбор выполняется по правилам и результатам бенчмарков.

### Задача

Использование одной дорогой LLM для всех запросов может создавать лишние затраты,
а выбор дешёвой модели — ухудшать ответы на сложные вопросы.
Маршрутизатор должен выбирать подходящую модель для каждого запроса:

1. Использовать домен, указанный клиентом, или определить его автоматически по тексту.
2. Подобрать модели с подходящими результатами бенчмарков для домена и языка задания.
3. Учесть признаки сложности, ограничения по расходам и времени, разрешённых провайдеров.
4. Вызвать выбранную готовую LLM через локальный сервер или облачный API
   и вернуть ответ с моделью, провайдером и причиной выбора.

Доменный автоподбор сравнивается с фиксированной моделью и самым дешёвым
допустимым вариантом. Основные метрики — разница качества ответов,
задержки p50/p95/p99, расходы на токены и полная стоимость запроса,
общая и накопленная чистая экономия после внедрения. Учитываются облачные
тарифы, локальные вычисления и работа роутера. В режиме локальной обработки
резервный вызов также остаётся среди локальных провайдеров.

## Воспроизведение

Python 3.11+, CPU; GPU и API-ключи не нужны. Из корня репозитория:

```bash
git switch hw_2
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell вместо source:
# .\.venv\Scripts\Activate.ps1
python -m pip install -e ".[eda,dev]"
python scripts/fetch_data.py
python scripts/eda.py
python -m unittest discover -s tests -v
python -m ruff check .
python -m ruff format --check .
```

`fetch_data.py` загружает пять публичных файлов по закреплённым URL и проверяет
их хеши; при повторном запуске использует проверенный локальный кеш. Сырые
снимки не публикуются в Git. Для загрузки данных, установки пакетов
и первой загрузки публичного словаря tiktoken нужен интернет.
Для offline-перезапуска сохраните `TIKTOKEN_CACHE_DIR` после первого прогона.
EDA проверяет данные статически и не исполняет программы HumanEval.
Графики/CSV/JSON перегенерируются скриптом; текстовые выводы находятся в отчёте.

Для pre-commit: `python -m pre_commit install`, затем
`python -m pre_commit run --all-files` (при установке хука в Windows при
необходимости используйте `python -X utf8 -m pre_commit install`).

## Состав репозитория

| Путь | Содержание |
| --- | --- |
| `docs/ml_system_design_doc.md` | Дизайн системы, обновлённый по результатам EDA |
| `reports/eda.md` | Анализ и решения по данным |
| `reports/figures/` | Шесть визуализаций |
| `reports/tables/` | Метаданные заданий и агрегаты для проверки расчётов |
| `data/raw/`, `data/licenses/` | Локальный кеш данных (вне Git) и тексты лицензий |
| `data/sources.lock.json` | Версии, URL, размеры и контрольные суммы |
| `scripts/` | Получение/проверка данных и воспроизводимый EDA |
| `tests/` | Проверки целостности, переводов и группировки |

Публичный корпус предназначен для диагностики и не доказывает экономию или
качество на новом потоке. Разбиение в EDA иллюстративное: Belebele не используется
для обучения/настройки. Для честного acceptance-test описан дополнительный сбор.
