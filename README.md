# ML_Sys_Design_HW

Проектный репозиторий курса по дизайну ML-систем.

Работы ведутся в ветках `hw_n` и попадают в `main` через pull request.

## Smart LLM Router — интеллектуальная маршрутизация между моделями

**Направление:** LLM.

Цель проекта — разработать систему автоматического выбора LLM с учётом сложности
запроса, предметной области и языка. Выбор будет опираться на бенчмарки качества
моделей в разных доменах и языках, стоимость и задержку инференса, чтобы обеспечить
баланс между качеством ответов, временем ожидания и затратами.

### Планируемый сценарий работы

1. Пользователь отправляет запрос и ограничения по стоимости и времени ответа.
2. Система определяет язык, предметную область и оценивает сложность запроса.
3. Маршрутизатор сравнивает доступные модели по результатам бенчмарков,
   оценке стоимости и задержки и выбирает подходящую модель.
4. Запрос передаётся выбранной модели, а ответ возвращается пользователю.
5. Метрики качества, задержки и стоимости используются для оценки маршрутизации.

Качество выбранной модели для конкретного запроса заранее неизвестно:
бенчмарки дают оценку для соответствующего домена и языка.

### Оценка результата

- Качество ответов на отложенном наборе запросов по доменам и языкам.
- Средняя стоимость запроса.
- Задержка ответа: p50 и p95.
- Доля запросов, уложившихся в заданные ограничения.

Планируется сравнение с базовыми стратегиями: всегда выбирать одну фиксированную
модель и всегда выбирать самую дешёвую доступную модель. Численные цели будут
определены после выбора моделей и набора данных.

## Текущий этап: домашнее задание № 1

Подготовлено окружение для разработки:

- Ruff проверяет Python-код, сортировку импортов и форматирование.
- pre-commit запускает Ruff перед каждым коммитом после локальной установки хуков.
- README содержит описание проекта и инструкции по работе с репозиторием.

Маршрутизатор, интеграции с LLM и бенчмарки пока не реализованы.
Ключи API для настройки репозитория не требуются.

## Требования

- Python 3.11 или новее.
- Git.
- Интернет для установки зависимостей и первого запуска pre-commit.

## Подготовка окружения

Клонируйте репозиторий и перейдите в ветку задания:

```shell
git clone https://github.com/Mixlazer/ML_Sys_Design_HW.git
cd ML_Sys_Design_HW
git switch hw_1
```

### Windows (PowerShell)

Команды используют Python из виртуального окружения напрямую; активировать его
и менять политику выполнения PowerShell не требуется. Режим UTF-8 при установке
хука обеспечивает корректную запись путей с кириллицей для Git.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -X utf8 -m pre_commit install
.\.venv\Scripts\python.exe -m pre_commit run --all-files
```

### Linux / macOS

```shell
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pre_commit install
.venv/bin/python -m pre_commit run --all-files
```

Хуки нужно установить один раз в каждой локальной копии репозитория.
Если хук исправил файлы, проверьте изменения, повторно добавьте их через `git add`
и повторите коммит.

## Ручная проверка

В Windows:

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
```

В Linux / macOS замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`.
Для автоматического исправления используйте `ruff check --fix .` и `ruff format .`
с тем же интерпретатором: `python -m ruff ...`.

Настройки находятся в `pyproject.toml`. Используется длина строки 100 символов;
проверяются ошибки Python, неиспользуемые импорты, порядок импортов,
типичные ошибки и возможность использовать современный синтаксис Python.
Версия Ruff в `requirements-dev.txt` совпадает с версией хуков.

См. [документацию Ruff](https://docs.astral.sh/ruff/integrations/#pre-commit)
и [документацию pre-commit](https://pre-commit.com/#install).

## Структура репозитория

```text
src/smart_llm_router/__init__.py  — заготовка Python-пакета
pyproject.toml                  — настройки линтера и форматера Ruff
.pre-commit-config.yaml          — хуки перед коммитом
requirements-dev.txt            — зависимости для разработки
.gitignore                      — исключения для Git, включая окружение и секреты
.gitattributes                  — единые переводы строк LF
README.md                       — описание проекта и инструкции
```
